# 日本酒ログ

## 既存公開版との互換性（2026-11-06）
- main 22d3b1b の料金ログの日付型対応を保持する。
- 部分更新で省略された`確定項目`・`推定値JSON`は保持し、明示送信時だけ更新する。
- `drive.file`では`DriveApp`を使わず、写真は既存のAdvanced Drive v3で保存する。
- GASのコード保存後は、既存デプロイを新バージョンへ更新して反映する。

ラベル・瓶を撮影すると、AIが銘柄情報を読み取り、本人の8項目（10段階）の評価候補を出す。さけのわは銘柄名・蔵元の照合に利用する。みんなの6軸評価は表示・AI入力に利用しない。iPhone専用のPWA。個人利用のみ。

## 構成
- 画面: GitHub Pages（このリポジトリ直下）。`index.html` / `css` / `js` / `vendor`（Fuse.js、browser-image-compression）
- 連携: Googleアプリスクリプト `gas/Code.gs`（AI呼び出し・スプシ保存・写真保存・料金ログ）
- データ: ドライブ「日本酒テイスティングログ」（記録）。さけのわは `data/sakenowa.json`（手元に保持）
- 記録は `gas` のスクリプトプロパティ `SHEET_ID` の先に書く。試験は「_テスト用」のスプシで行い、本番に試験データを書かない

## 鍵と合言葉（コードに書かない）
スクリプトプロパティ: `ANTHROPIC_KEY` / `TOKEN`（合言葉）/ `SHEET_ID` / `USDJPY`（任意、既定155）。
合言葉はiPhoneのアプリ「設定」に入れる。合言葉のない呼び出しはすべて断る。

## 更新
- さけのわを更新: `python3 build/update-sakenowa.py`（月1回ほど）
- GASを更新: `cd gas && clasp push -f`、続けて `clasp deploy -i <デプロイID>`
- 画面を更新したら `sw.js` の `V` と、`index.html` の `?v=` を上げる

## 守ること
- 開発方針: 共通ナレッジ `システム手帳_開発方針.md`（横ずれ・バウンド・ヘッダー固定・保存は差分のみ）
- アイコンは絵文字ではなく画像（ChatGPTで作成）
- 表記: 「さけのわデータを利用しています」とsakenowa.comへのリンクを常に出す
- 本人の8項目は10段階。旧数値1/2/3は2/5/8、既定の余韻5語は既存換算表で表示し、原値・原文も示す。未知の文字評価は原文で表示し、数値を作らない。表示換算だけで元シートを書き換えない。
- 保存はpreserve-v1/scoreEditsで明示変更軸だけを更新。既存行全体の評価尺度は維持し、変更軸の尺度・由来・原値を評価尺度JSONに記録する。評価尺度JSON列は最初の明示変更時に追加する。旧GAS・旧キャッシュと混在して保存情報が足りない場合は保存を止め、同期を案内する。
- 登録用の新規下書きと既存記録の編集を起動中のメモリ内で分離する。新規保存成功後の登録は次の新規下書き、同じ結果の再保存は既存更新。失敗時は下書きを保持する。登録へ戻るだけで書きかけを消さない。
- 銘柄照合は名称レベルであり、酒種・製法・原料・精米歩合の完全な商品同定とは扱わない。参照JSONの物理削除はしない。

## 保存の整合性

- 評価値、評価尺度JSON、保存操作JSON、同じ保存で変える他のセル・追加ヘッダーを、Sheets API v4の1回の`spreadsheets.batchUpdate`へまとめる。変更セルの`userEnteredValue`だけを書き、関係ないセル・書式・数式を再書込みしない。数式のある対象項目は更新を拒否する。`=...`で始まる入力は文字列として保存する。
- Apps Scriptの既存spreadsheets/external_requestスコープと、実行時の`ScriptApp.getOAuthToken()`を使う。Advanced Sheets v4（識別子Sheets）と既存のDrive v3をmanifestに定義する。既存デフォルトCloudでSheets連携を追加し、試験用シートへの保存4操作でAPI利用を確認済み。利用できなければ写真保存前の読取りで停止し、勝手に認可を進めない。
- 保存操作JSON列は最初の保存時、評価尺度JSON列は最初の評価変更時に、保存する行と同じバッチで追加する。既存行全体の尺度変換や16件の一括移行はしない。操作IDは非秘密の再送識別子で、認証能力はない。
- スクリプトプロパティには操作ID、要求のハッシュ、対象行、結果バージョン、変更列・ハッシュ等の確認情報だけを保存する。合言葉/APIキー/写真/メモ本文を追加保存しない。確認済み情報は7日、最大200件。対象名前空間の期限切れ確認情報だけ整理し、既存設定には触れない。未確定の待機情報を自動で期限切れ解除しない。
- API応答消失時は新鮮なGridDataで操作記録と変更セルを照合する。確定できなければそのシートの保存を停止し、自動再送しない。同じ要求の手動再試行は同じIDを使う。未確定後に下書きを変えた場合も新しいIDで黙って保存しない。端末を閉じると下書き/操作IDは保持されないが、サーバーの待機障壁は残る。
- Drive写真とSheetsは別のサービスのため、写真まで含めた分散トランザクションではない。写真の応答消失、一部写真だけ成功、写真作成後のシート拒否では保存を停止して管理者確認を求め、写真の再送/無断削除をしない。
- 未確定の待機情報を削除して再保存する運用は禁止。対象シートの保存操作JSON、Drive、確認情報を調べ、遅延要求がまだ実行し得るかも確認してから個別に復旧する。今回、自動的な強制解除UIは作っていない。
- スクリプトロックと元行バージョン確認はアプリ経由の同時保存を防ぐ。シートを直接編集する他者との間に条件付き更新/CASは提供されないため、手動編集とアプリ保存の同時操作は避ける。バッチの原子性は他者の将来の変更を禁止するものではない。

根拠: [Google Sheets batch requests](https://developers.google.com/workspace/sheets/api/guides/batch)、[ScriptApp.getOAuthToken](https://developers.google.com/apps-script/reference/script/script-app#getoauthtoken)。

## 表示領域の復帰

PWA/通常ブラウザの休止時の高さはCSSの100dvh（非対応環境は100%）に任せる。root.clientHeightとinnerHeightの最大値等で広げない。キーボードは独立したCSS計測の上限と幅に適合する場合だけ制約し、画面/設定の遷移、有限回の再計測で解除する。hidden/pagehide中は更新せず、世代の古い遅延処理を無効化する。safe areaの加算やscreen.heightを使わない。診断は寸法/資材版だけで秘密値・記録を読まず、自動送信しない。CSS自体の誤報や古い起動中ページは、実機情報なしに判定/補正できない。
